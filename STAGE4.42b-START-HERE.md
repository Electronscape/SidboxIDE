# GamerGirl Stage 4.42b — Adventure Rules (the architecture clarification)

Base: Stage 4.42 generated from the user's 21 October 2026, 11:08 **known-good** IDE snapshot. This replaces the **partial** Adventure templates from Stage 4.42; it does **not** change game physics, world objects, GUI helpers, SPC/audio, or programmer-owned `main.c`.

## What the SDK now owns

The canonical Adventure runtime sources in the IDE are now:

- `idelibs/codehelpers/game/adventureruntime.rulec`
- `idelibs/codehelpers/game/adventureruntime.ruleh`

These **are not C files to compile directly**. At project-update time the IDE reads them, binds `@IDE{...}` values using `gamehelpertemplates.h`, and emits ordinary C/H to the game project:

- `gamehelpers/gameadventureruntime.c`
- `gamehelpers/gameadventureruntime.h`

The naming is deliberate: the IDE has a **rule template**, while the project receives **compiled C source**. Game helpers not yet migrated continue to use `.c/.h` as their template sources and remain unchanged. No GUI helper files have been touched.

### Every project-editable runtime property is now bound

| Rule token | Adventure Editor field / meaning |
|---|---|
| `@IDE{DIALOG_X}` | Dialogue box X |
| `@IDE{DIALOG_Y}` | Dialogue box Y |
| `@IDE{DIALOG_WIDTH}` | Dialogue box width |
| `@IDE{DIALOG_HEIGHT}` | Dialogue minimum height |
| `@IDE{TEXT_COLOUR_INDEX}` | Foreground text colour index |
| `@IDE{TEXT_OUTLINE_ENABLED}` | Use text outline (0/1) |
| `@IDE{OUTLINE_COLOUR_INDEX}` | Text outline palette index |
| `@IDE{TILE_SIZE}` | Dialogue nine-slice atlas tile size |
| `@IDE{FRAMES_PER_CHAR}` | Typewriter animation speed |
| `@IDE{ITEM_COUNT}` | Configured inventory types (metadata) |

Fixed engine rules `@IDE{MAX_ITEMCOUNT}`, `@IDE{GA_COLS}`, and `@IDE{GA_LINES}` are also resolved. The inventory **storage capacity stays 64**, independent of the current inventory size, to preserve generated-story compatibility.

**Runtime state is not configuration.** Pointers, animation timers, dialogue progress, counters, frame buffers, and functions remain ordinary C so the engine can update them while running. The designer edits only the project's configurable defaults.

**There is no competing configuration source:** `gameadventuregen.cpp` no longer writes another dialogue position or text style into `gameadventure_setup()`. It references the runtime rule header's exported macros for tile size and typing delay. `game_adventure_start()` initializes its settings from the rendered runtime rules. The public setter APIs remain available for *optional programmatic overrides*.

**Still generated by the IDE in this stage:** `gameadventure.c/.h` with actual item, NPC, choice and dialogue data; skin-cell/flip arrays; links to sprites and user actions. Migrating those **data tables** to `gameadventure.rulec/.ruleh` is a separate, testable next stage. This step converts the reusable **runtime** only, not every game generator at once.

## Crucial update paths

All three routes read `.rulec/.ruleh` and write normal `.c/.h`:

1. **Update Game Project** — fully resolves and validates helpers **before** its existing ZIP backup and transactional update. Unresolved/unknown `@IDE` placeholders cause a clear error. This is the preferred upgrade route.
2. **Generate Game Code** — installs missing helpers from the rules. If a pre-existing project's Adventure runtime header is too old, the IDE now **stops and tells you to run Update Game Project first** rather than producing code that cannot compile.
3. **Add Helper Code → Game** — discovers `.ruleh` helpers and renders the pair. **Add Helper Code → GUI is unchanged.**

## Installing the changed-files ZIP safely

1. Back up your **working IDE and game**.
2. Extract the changed-files ZIP **into the IDE source root**, preserving paths.
3. IMPORTANT: If the original files still exist in the IDE's SDK folder, delete or move aside **only these two obsolete IDE-SDK source templates**:
   - `idelibs/codehelpers/game/adventureruntime.c`
   - `idelibs/codehelpers/game/adventureruntime.h`

   Keep the new `.rulec` and `.ruleh`. The IDE will choose `.rulec/.ruleh` even if old files remain, but deleting them prevents accidental edits to stale, unused code. **Do not delete the game's** `gamehelpers/gameadventureruntime.c/.h` — Update Game Project replaces those for you.
4. Rebuild GamerGirl with your normal Fedora Qt6 process.
5. Open a **copy** of your known-good Adventure project. Use **Update Game Project** (not only Generate Game Code); accept the ZIP backup.
6. Inspect `gamehelpers/gameadventureruntime.c/.h`: no `@IDE{` markers. Project-specific dialogue X/Y/size, text colours, outline, and typing speed must match the Adventure Editor, not template defaults.
7. Compile and run on SIDBOX. Check inventory, flower, completed NPC greeting, dialogue height, typewriter text, animations, and foreground text/outline.

**Proof of independent helper maintenance:** after a successful hardware test, change a comment or an internal algorithm in the SDK `.rulec`, without touching the IDE C++ files. Click **Update Game Project** again. Your helper change should appear in `gameadventureruntime.c` without rebuilding the IDE. New rule token bindings, public APIs, or engine features still require an IDE update.
