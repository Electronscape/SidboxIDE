SIDBOX / CoderGirl IDE Stage 5.166.14 (27 October 2026)
V1 GAME PROJECT RAM BUDGET GUARD

Install over Stage 5.166.13:
1. Extract CoderGirl-Stage5.166.14-271026-DROPIN.zip at the IDE source root.
2. Rebuild the Qt6 desktop IDE.
3. Splash: Build: 5.166.14.271026.
4. Rebuild your V1 Game project. If the linked RAM usage exceeds Project
   Settings > Applet size, CoderGirl now displays a warning with a suggested
   setting that leaves at least 10% budget headroom (16 KiB increments).
5. Choose "Increase ... and continue" to save the new allowance to the
   project's .proj and regenerated default .ld, then continue generating .asm
   and .app WITHOUT re-compiling the unchanged game sources.
6. Choose "Keep ... and stop build" to retain settings and STOP before
   publishing the new .app. The existing .app file remains unchanged.

How it works
- Checks the actual _appstart..__stack_end__ ELF RAM span, including BSS,
  data and reserved stack, not the smaller on-disk .app size.
- Uses arm-none-eabi-nm when available, falls back to the generated linker .map.
- If both tools fail to produce usable addresses, refuses to publish an
  unverified V1 Game .app under the default linker. Custom linker script
  projects retain control of their own memory allocations.
- Protects the default game's 6 MiB SDRAM layout: 128 KiB RAM disk plus
  reserved MOD space reduce the maximum sensible applet budget.
- V1 GUI / V2 builds retain their pre-existing handling.

Verified against user-uploaded Platformer3 example:

  __stack_end__: 0xD00822D8

Important distinction: the 113% was an overrun of the user-selected planning
budget, not proof of an overflow beyond physical SDRAM. The default game
linker currently permits the rest of game SDRAM, which explains its success.
