# CoderGirl Stage 5.154.261026: Lightning-aware Spotlight + Named Weather Status

Install over **Stage 5.153.261026**. This additive change keeps the existing rain/snow/thunder, palette flashes, particles and current `main.c` draw order.

## New world setting

Open **Game Designer → Player Start / World Entry Point → WORLD WEATHER** and enable:

**Suspend spotlight during lightning flashes**

- Applies only to **Thunderstorm**, and only to the **bright frames** of a lightning burst. The spotlight is drawn again automatically in the dark gap between pulses and after the burst.
- No changes are made to the spotlight's actual enabled state, user-driven spotlight toggles, brightness/fade values, front or back `.pal` files, or other world effects.
- **Off by default for existing projects**. This protects Stage 5.153 visuals until you choose to change them.
- Saved in the world `.sbgm` weather object as `suspendSpotlightOnLightning`. The world-registry generator exports one flag per world. Switching worlds loads each world's own option.

**Important:** The option skips drawing the darkness mask for bright lightning frames. It does not alter previously drawn sprites, the player's physics, or weather flash rendering.

## New named weather status API

The generated `gamehelpers/gameworlds.h` now defines:

```c
#define GAME_WEATHER_STATUS_NONE           0u
#define GAME_WEATHER_STATUS_PRECIPITATION  (1u << 0)
#define GAME_WEATHER_STATUS_LIGHTNING_FLASH (1u << 1)

uint8_t gameworlds_weather_status(void);
uint8_t gameworlds_weather_frame(uint16_t view_width, uint16_t view_height);
```

These are **bit flags**. `GAME_WEATHER_STATUS_LIGHTNING_FLASH` indicates that lightning is currently making the scene brighter. It is **not** set during the dark gap in the double-flash sequence. The `PRECIPITATION` bit indicates active rain, snow or thunderstorm precipitation.

`gameworlds_weather_frame()` still draws rain/snow and lightning as before, and additionally returns those bits. Calls which ignore this new return value continue to compile and run unchanged.

### Do I need to edit `main.c`?

**No**, when using the checkbox. Keep your existing calls:

```c
/* Scene/world/FRONT tiles and player were already drawn. */
gameworlds_spotlight_frame(VIEW_W, GAME_PLAY_H);
gameworlds_weather_frame(VIEW_W, GAME_PLAY_H);
/* HUD and dialogue are drawn afterwards. */
```

If you prefer manual per-frame logic **instead of ticking the checkbox**, check the status **BEFORE** drawing the spotlight. The returned value from `gameworlds_weather_frame()` arrives too late to control the earlier spotlight call on the same frame:

```c
uint8_t weather = gameworlds_weather_status();
if ((weather & GAME_WEATHER_STATUS_LIGHTNING_FLASH) == 0u)
    gameworlds_spotlight_frame(VIEW_W, GAME_PLAY_H);

/* Still render the precipitation and flash after the spotlight stage. */
(void)gameworlds_weather_frame(VIEW_W, GAME_PLAY_H);
```

Call `gameworlds_update(1)` once per simulation frame, as before, before the scene draw. Do NOT update weather twice.

## Installation / hardware testing

1. Install the drop-in over Stage 5.153, rebuild and launch CoderGirl.
2. Open the intended world, choose Thunderstorm, enable the new spotlight checkbox, save the design.
3. **Update Game Project**, rebuild/upload the game to SIDBOX.
4. Observe a storm with spotlight enabled: darkness should vanish only on lightning's bright frames, returning between and after flashes.
5. Compare with the checkbox unchecked, then optionally test `Palette flash strength > 0` and another world with clear weather.
