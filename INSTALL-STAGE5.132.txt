CoderGirl Stage 5.132.251026 — Trigger / Switch accepts dropped items
===================================================================
BASE: Stage 5.131.251026. Extract the DROPIN ZIP over the Stage 5.131 IDE
source root with paths preserved, then rebuild the Qt6 IDE.
Qt6 requirement: existing project baseline (6.5 or newer). No Qt6 SDK in
this container to perform the final graphical IDE build.

SETUP IN THE EDITOR
1. Configure the object as Trigger / Switch and give it a real sensor hitbox.
2. Set "Interact with inventory item" to a named Adventure Inventory item.
3. Tick "Activate when matching dropped item touches switch".
   This option is disabled until an inventory item is configured. A red
   outline identifies disabled dependency controls, green enabled ones.
4. Set "Consume used / dropped item on success":
   TICKED = the physical dropped item disappears on success.
   UNTICKED = the item remains available for pickup, but cannot retrigger
   this switch by remaining on the floor. Its activation flag persists
   when leaving and revisiting the world.
5. Configure On success dialogue, dialogue mode, reward, stat/sounds, linked
   actions and one-shot as usual. All work for matching dropped items.
6. In the Adventure Inventory definition, enable Drop for the selected item.
7. Save, click Update Game Project, then rebuild the SIDBOX game.
   Do NOT overwrite your user-owned main.c.

BEHAVIOUR
- Dropped item movement and gravity from 5.131 remain unchanged.
- Collision checks test the falling 16x16 item at each vertical pixel.
- Contact is with the Trigger sensor hitbox; no FIRE2 is required for DROP.
- Wrong dropped items do not activate or show the wrong-USE dialogue.
- Existing FIRE2 item USE still works separately.
- Rewards are preflighted before consuming/triggering. If inventory is full,
  the drop remains and the interaction doesn't complete.
- One-shot triggers deactivate after success, same as existing USE.
- The saved drop struct remains EXACTLY 12 bytes: the existing 'armed'
  byte reserves bit 1 for once-per-drop activation (bit 0 remains pickup
  re-arming). Older world snapshots remain compatible.
- This affects the generated game runtime. Existing saved .sbgm fields are
  backward-compatible; triggerDrop defaults false.
- No change to player hitbox, foot-anchor, tilemap collision, or firmware.
