SIDBOX CoderGirl Stage 5.81 - Inventory and Adventure Editor
Build: 5.81.241026

INSTALL (BACK UP FIRST)
1. Close CoderGirl. Extract IDE/ contents into your IDE root, preserving directory paths.
2. Extract Platform3Test/ contents into your Platform3Test game root.
3. Rebuild the IDE. Open Adventure Editor > Inventory Items in EACH world to configure
   Maximum inventory slots (0 = unrestricted) and each item's Can Drop and Can Discard.
   NPC-required items cannot be permanently discarded, but Can Drop is allowed.
4. Save each .sbgm. Use Update Game Project to regenerate world story code,
   then rebuild/re-copy your game to SIDBOX/TFCard as usual.

FEATURES
- Newly acquired items (including additional copies of a stack) sort first.
  Order by item name survives world switching in the same running game.
- Four inventory entries visible. Up/down navigates with ^/v scroll hints.
- Can Drop and Can Discard are independent. Legacy Can Discard=true items
  are initially also Can Drop=true; safe migration of previous game behaviour.
- Max inventory slots 0..64, counting distinct occupied item stacks.
  Multiple units of the same item count as one slot.
- Regular tracked collectables are NOT removed while the backpack cannot
  accept them. NPC choice/close gifts remain pending; full bag is explained.
- Pickup-from dropdown visually compresses array objects with contiguous indexes:
  foo[0..5], foo[9..12]. A complete zero-based contiguous group becomes foo[].
  Visual grouping does not change pickup type/kind matching.
- Persistent floor drop artwork fix from Stage 5.80 retained.

NOTES
- Capacity is stored per world in its adventure data (maxInventorySlots).
  Set it in each world where you want the same limit.
- The game files included here retain the original zero/unlimited limit until
  you explicitly configure and save it in the IDE and regenerate world code.
- DO NOT replace or edit your custom main.c. No user game design or save files modified.
- The generated story .c copies in the drop-in preserve existing style defaults;
  custom Can Drop/Can Discard selections come from saving the Adventure Editor
  and running Update Game Project.

VALIDATION
