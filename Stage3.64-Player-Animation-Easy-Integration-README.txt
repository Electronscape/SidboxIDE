GAMERGIRL STAGE 3.64 - EASY PLAYER ANIMATION INTEGRATION
=========================================================
Base: complete Stage 3.63 (including 3.62 Player Animation Editor).

THE PROBLEM
-----------
The .sbanim file is editable project metadata. Stage 3.62's Export V1 C
Header creates the runtime animation playback C, but generated
maingame.c.txt did not contain any actual calls to that exported playback.
So the player remained on its original static BOB atlas index.

THE FIX
-------
EXACT SOURCE FILE MODIFIED: gamedesigner.cpp
EXACT FUNCTION MODIFIED: SidboxGameDesigner::exportExampleMain()

When the Game Designer's Sprite NAMED "player" has saved Player Animations,
Update Game Project now generates maingame.c.txt with a documented,
opt-in animation controller already wired into the existing game loop.
It requires NO new helper .c, no new physics APIs, and no firmware updates.
The feature is OFF by default, so existing projects compile as before.

QUICK START
-----------
1. Back up your IDE and game project, then rebuild this IDE source.
2. In Game Designer, select the Sprite named "player" and click
   "Player Animations...". Add at least one frame for each default state:
      Idle -> Right       Walk -> Right
      Jump -> Right       Fall -> Right
   Check "Mirror left from right". Set frame timing, Save Animations,
   and SAVE THE GAME DESIGN (.sbgm) so the Sprite link is retained.
3. In Player Animation Editor click "Export V1 C Header..." and choose
   EXACTLY this filename relative to the GAME PROJECT root:
      gameanimations/player_anim.h
   The filename controls the public C symbol prefix: player_anim.
   Export it again whenever your animation states/frames/timing change.
4. In Game Designer choose "Update Game Project". It now produces a new
   maingame.c.txt containing the "PLAYER ANIMATION -- ONE-SWITCH SETUP"
   block (if the player's animationFile field is saved in the .sbgm).
5. If main.c is still IDE-owned, it can also be regenerated automatically.
   If main.c is USER-OWNED, it is protected and is NOT replaced; copy the
   animation sections from maingame.c.txt into your own main.c.
6. In the C file you are actually building, change:
      #define GAMERGIRL_PLAYER_ANIMATIONS 0
   to:
      #define GAMERGIRL_PLAYER_ANIMATIONS 1
   Rebuild the V1 game and transfer it to SIDBOX.

WHAT THE STARTER DOES
---------------------
- Keeps the game's existing game_tile_player_run() movement/physics.
- Calls animation selection AFTER player physics and BEFORE gfx_drawbob().
- Press RIGHT -> Right; press LEFT -> Left (inherited X-flip if configured).
- Release direction -> remembers the last facing direction.
- Grounded, no sideways input -> Idle.
- Grounded with sideways input -> Walk.
- Airborne with negative vertical velocity -> Jump; falling -> Fall.
- Uses the named frame indices exported by the Animation Editor;
  runs one 50Hz tick per displayed frame.
- Doesn't need a separate .sbanim file on the SD card. That file is editor
  metadata. The original image needs to be a SIDBOX-compatible indexed PPB
  atlas with the SAME cell geometry used by Player Animation Editor and
  colour-index-zero transparency.

LATER CUSTOMIZATION
-------------------
This basic startup handles Idle/Walk/Jump/Fall, not Run/Push/Hurt/Slide,
because your game's actions and speed thresholds are not guessed. You can
select those additional states in the same player_anim_state section once
you have real game conditions (e.g. push flag, running speed, hurt timer).
If you've renamed/deleted Idle/Walk/Jump/Fall from the editor, the matching
C enum references must be updated in your main.c (or restore state names).

IMPORTANT: USER-OWNED main.c IS NOT OVERWRITTEN
------------------------------------------------
Since Stage 3.52, saving edits to main.c marks it user-owned. Update Game
Project deliberately never overwrites it. Use maingame.c.txt as the
up-to-date example and manually integrate those code sections into main.c.
Do NOT throw away your custom game code to get animations working.
