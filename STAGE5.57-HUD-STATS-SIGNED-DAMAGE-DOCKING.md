# SIDBOX / CoderGirl Stage 5.57.231026

## Changes

1. **HUD numeric stats:** Health, Lives, Score and shared Player custom stats (e.g. Fear/Magic) are draggable under **Drag numeric player stats onto HUD**. Numeric fields are saved in `gamehud.sbhud` as `numericStats`, rendered in the editor, and regenerated into `gamehelpers/gamehud.c`. The old v1 HUD format is retained; existing counters and animated bars are unchanged. Drag to move, double-click to edit the displayed label, right-click to remove.
2. **Enemy / Hazard signed stat changes:** `Game Object Properties -> Damage / Knockback / Hurt Effects` now contains a **Damage target stat** dropdown (Health, Lives, Score, Coins, custom named stats) and **Stat change (+/-)**. E.g. `-10` removes 10, `+5` adds 5. One stat update per *accepted* collision event, respecting existing contact grace, flash and hurt logic. Values saturate rather than wrap. The Coins setting adjusts inventory pickup kind 1, honouring the bag's item capacity; HUD-only coin counts also work. `damageTarget` and `damageDelta` are saved per object in `.sbgm`, defaulting to the prior health damage setting for older projects. Existing old `hazardDamage` fields are kept for old/custom code compatibility.
3. **HUD dock placement:** **HUD placement** supports Overlay (original), Dock Top, Dock Bottom. A docked HUD must be exactly 480 pixels wide (columns x cell width) and shorter than 320 px. Dock height is the HUD's pixel height. With docking enabled, the generated game loop follows the player within the reduced-height play area, draws tilemaps with that viewport height, crops the foreground framebuffer (column-major SIDBOX format, **not** row-major), shifts the playfield down for a top dock and draws the HUD in the reserved strip. No resampling, new PPBs or changed CLUT indices. Overlay is the default for legacy HUDs.

## Important: an existing user-owned `main.c`

**CoderGirl NEVER overwrites a user-owned `main.c`.** Regenerate the project first, then compare the new `maingame.c.txt` with *your* project's `main.c`. If you own it, add these parts manually or the IDE changes will compile but the old damage and overlay drawing will still run:

- Near the view macros, define `GAME_PLAY_H` as `VIEW_H - gamehud_dock_height()` with `HAS_HUD`; otherwise `VIEW_H`.
- In the render loop, centre and clamp `camera_y` using `GAME_PLAY_H`; use `GAME_PLAY_H` for the height argument to **both** `game_tilemap_blit_view_cleared()` and `game_tilemap_blit_view_front()`.
- After all world/player/foreground drawing, **before** `game_show_hud(0,0)`, invoke `gamehud_apply_dock(front[draw_index]);`.
- For circle masks with a top dock, call `gameworlds_transition_camera(camera_x,camera_y - (gamehud_dock_top()?gamehud_dock_height():0));`.
- In the block accepting `world_player.hurt_triggered`, process `hurt_stat_target`, `hurt_stat_delta` and `hurt_stat_name` instead of unconditionally subtracting `hurt_damage_this_frame` from the old demo health variable. Copy the complete accepted-hit switch from regenerated `maingame.c.txt`.
- Ensure Health and Score display use `gameworlds_state()` (the project-wide persistent player state), and that custom stat reads go through `gameplayer_stat_get()`.

The generated HUD functions (`gamehud_dock_height`, `gamehud_dock_top`, `gamehud_apply_dock`) reside in `gamehelpers/gamehud.c/.h` and are generated by saving the HUD or running **Update Game Project**.

### Dock artwork / background plane

The reserved dock strip uses the indexed foreground pixels and the designer's existing HUD artwork. For a solid opaque panel, fill the HUD's **entire 480-pixel width** with non-transparent tiles. On dual-plane games transparent HUD pixels may let the background plane show through. Only the foreground scene is cropped; background plane assets remain the existing background implementation. Drawing a full-screen translucent or tiled background is outside this change.

### Performance

Top docking performs a per-frame `memmove` for 480 framebuffer columns. It does not alter the allocated framebuffers or change screen mode. This needs a **real STM32H743 performance test** to check 50 FPS, scrolling and transitions before calling the feature hardware-accepted.

## Recommended acceptance test

1. Unpack Stage 5.57 over Stage 5.56 and rebuild the IDE.
2. Drag **Health** and the custom **Fear** stat from the new numeric stat list onto your HUD. Save and reopen; confirm placement and numbers.
3. Open an enemy or hazard, choose `Health / -10`; choose another one with `Fear / +5`. Save world(s).
4. Make your HUD `480 px` wide; select Dock Top or Dock Bottom, save.
5. Run **Update Game Project** on **all worlds**; integrate `maingame.c.txt` into hand-owned `main.c` as explained above.
6. Rebuild the game and test one hit per contact, health clamping at zero, Fear increase/decrease, score and coin changes, both docks, scrolling near map boundaries, and IN/OUT world transitions. Measure 50 FPS for top docking.
7. Switch HUD placement back to Overlay, regenerate and check unchanged original gameplay.
