# GamerGirl Stage 4.51 — Remaining V1 Game Generators to Rules

Based on Stage 4.50 (the version verified on physical SIDBOX hardware).

## New SDK rules (inside idelibs/codehelpers/game)

- `gameassets.rulec` / `gameassets.ruleh`: complete Game Assets runtime code. Has 27 repeatable sections for bitmap/palette declarations, direct background conversion, resource loading and cleanup, sprite drawing, SFX and music. Qt supplies data values, pixels and configuration; no C functions are generated by QTextStream in gamecodegen.cpp.
- `level1.rulec` / `level1.ruleh`: tilemap declarations, embedded graphic/collision/flip/slope arrays, named collision zones, shape references, loop tracks, tilemap initializers, optional TFCard `.map` load/unload and atlas borrowing/loading.
- `splinepaths.rulec` / `splinepaths.ruleh`: generated path point arrays and declarations; Qt supplies point coordinates, pauses, duration, repeat and identifier.
- `playeranim.ruleh`: complete player animation runtime and optional automatic state selection. Header-only C is intentional; no corresponding `.rulec` is needed. Qt supplies validated state/direction names and animation frame/timing arrays.

No extra `.inc` files. Existing reusable `animation.c`, `tilemap.c`, `spline.c`, etc. remain ordinary drop-in helpers, unchanged.

## Modified Qt source

- `gamecodegen.cpp` / `gamecodegen.h`: load and validate Game Assets rule templates, expand repeatable sections, output ordinary `gameassets.c/.h` as before. Rules directory is explicit in Request.
- `gamedesigner_export.cpp`: supplies installed SDK rules location for Game Assets.
- `gametilemap.cpp` / `gametilemap.h`: render `level1.c/.h` from rules; SD/TFCard `.map` binary format, validation and checksum logic deliberately untouched.
- `gamedesigner.cpp`: supplies rule location to Tilemap Editor; exports spline paths from rules; hides project generators from Add Helper Code.
- `gameanimationeditor.cpp` / `gameanimationeditor.h`: render player animation headers from `playeranim.ruleh` and stop with a message if the rule is unavailable or invalid.

## Backwards compatibility / preservation

- Generated filenames, public function names, graphics modes, palette alpha handling, sound channels/parameters, music start selection, atlas share checks, palette-cycling order and spring/world-object logic are kept unchanged.
- No project-user `main.c` is modified by this migration.
- No change to `.map` bytes or SBMP version.
- Generated files are still written through existing atomic file operations.
- In the event of an unreadable or invalid rule, generation fails before its output is replaced.

## Static verification performed here

- 27 Game Assets named sections extracted successfully.
- Native GCC C syntax checked 64 resource configurations (embedded/external PPBs, single/dual display plane, direct backgrounds, sprite arrays, audio 8/16 bit, palettes, music).
- Native GCC C syntax checked 32 level variations, 12 animation variants, and 3 spline-path variants.
- Conditional directives balance; dynamic markers resolve; C outputs use their rule templates.

Qt 6 development files are not installed in this environment, so the **Qt IDE has not been compiled here**. The **physical SIDBOX has not been tested** for Stage 4.51.

## Testing on your machine

1. Back up your proven Stage 4.50 IDE and your game project.
2. Replace source files or extract the full archive; rebuild the IDE.
3. Generate Code / Update Game Project. Confirm `gameassets/gameassets.c/.h` and `gamelevels/level1.c/.h` generate and compile.
4. Re-export an existing spline and save player animations (including Mirror Left and Auto State where used); check the generated headers.
5. Try one embedded and one TFCard-loaded PPB path, direct background rotation/scrolling, palette cycles, music/SFX, springs, and collectables on SIDBOX.
6. Keep Stage 4.50 until this passes your hardware test.

All template code is SDK-managed; do not copy the `.rule*` into generated user projects.
