SIDBOX / CoderGirl IDE - Stage 5.166.29.271026 (27 October 2026)
Runtime World Map rendering fast path

CONFIRMED CAUSE
The V1 maingame.rulec template draws the entire gameplay world even while
World Map is open: background, game objects, back tilemap, player, NPCs,
front tilemap, spotlight, and weather. Only then does game_adventure_draw()
render the selected modal UI. The Quest Journal is NOT drawn under the map;
the adventure renderer chooses one modal at a time.

FIX
A new public getter, game_adventure_world_map_is_open(), reports ONLY World
Map state (unlike game_adventure_open(), which includes conversations,
inventory, saves, defeat screen and Quest Journal).

The generated main.c's frame renderer now clears the framebuffer and skips
the entire world-render block while that flag is true. It still executes:
- gamehud_apply_dock() and game_show_hud(): preserves HUD height/placement
- game_adventure_draw(): World Map with its four boundary-colour strips
- gameworlds_transition_frame(), framebuffer display/swap and music_update()
- gameplay-world restoration on closing the World Map

Ticking the animated gameplay tilemap is also skipped while the map is open.
Ambient simulation functions preceding the render path remain unchanged.
Other modal screens retain their previous world-behind-window behaviour.

FILES CHANGED
- idelibs/codehelpers/game/adventureruntime.ruleh (public getter)
- idelibs/codehelpers/game/adventureruntime.rulec (getter implementation)
- idelibs/codehelpers/game/maingame.rulec (world render gate)
- splashscreenwidget.cpp (Build: 5.166.29.271026)
- development/tests/test_stage5166_29_map_fast_path.py (native + generator tests)

IMPORTANT: YOUR USER-OWNED main.c
The IDE correctly protects your edited main.c! Updating the project updates
maingame.c.txt but WILL NOT insert the render gate into your main.c.

In your game's main.c, inside main(), find the screen drawing sequence:

    game_tilemap_animation_tick(1);
    /* Draw into the hidden buffer, then display and swap. */
    gfx_usebuffer(front[draw_index]);
    gfx_setcolour(0);
    gfx_rectf(0, 0, VIEW_W, VIEW_H);
    ... scene/background/tilemap/player/effects ...
    gameworlds_weather_frame(VIEW_W, GAME_PLAY_H);
    ... HUD, adventure_draw(), display, music_update() ...

Change it to this exact structure:

    /* Remove game_tilemap_animation_tick(1) from before the clear. */
    gfx_usebuffer(front[draw_index]);
    gfx_setcolour(0);
    gfx_rectf(0, 0, VIEW_W, VIEW_H);
    if (!game_adventure_world_map_is_open()) {
        game_tilemap_animation_tick(1);
        /* Keep ALL existing background, game-object, tilemap, player,
           spotlight and weather DRAW calls unchanged here. */
        gameworlds_weather_frame(VIEW_W, GAME_PLAY_H);
    }
    /* Keep your existing HUD, game_adventure_draw(), transitions,
       framebuffer display/swap and music_update() OUTSIDE this if. */

NOTE: The game_tilemap_animation_tick() line is present in the starter only
when a tilemap exists. If your main.c does not have that line, don't add it.
The exact positioning of the if/closing brace is visible in the updated
maingame.c.txt generated by the IDE; compare this against your own main.c.
Do not put the framebuffer clear or game_adventure_draw() inside the guard,
or the map disappears. Do not gate game_adventure_input(), because map
panning and closing need to keep working.

   5.166.29 HOTFIX over Stage 5.166.28 preserving directories.
3. Rebuild the IDE, verify Build: 5.166.29.271026.
4. Update ALL Worlds / Update Game Project, regenerating the Adventure
   runtime and maingame.c.txt.

   If user-owned, copy the render block as above into your own main.c.
6. Rebuild the V1 game, launch and compare frame rate in a complex world
   before/during/after the World Map, with and without HUD docking.
