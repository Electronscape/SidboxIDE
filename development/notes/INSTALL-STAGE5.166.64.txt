Independent Logic: RESULT -> Game Object enabled state
======================================================

ACTUAL FAILURE FROM UPLOADED GAME (Archive.tar(8).gz):
  world1.sbgm / logictest_key[0] / independent node logic1:
  TRUE -> logictest[2]: enable
  FALSE -> logictest[2]: enable
  Generated worlds/world1/gamehelpers/gameworlditems.c therefore wrote
  cg_gwi_platforms[22].active = 1 in BOTH branches. The AND expression
  itself correctly read logictest[0] && logictest[1].

NEW: Drag the AND node's teal RESULT socket directly onto logictest[2].
That creates a SINGLE typed direct state binding in the world .sbgm:
  resultTargets: [<stable ID of logictest[2]>]
The generated C sets object.active = logic_result ? 1u : 0u, executing
when the existing independent-graph trigger/state-change path fires.
The editor removes any conflicting TRUE/FALSE actions to the same target
from that logic node. Other actions, dialogues, graph links are preserved.

The tree opened by dropping RESULT in empty space now permits compatible
Game Objects as well as Logic nodes. A direct RESULT wire is teal and
supports right-click -> Remove Connection.

If users prefer two explicit TRUE/FALSE action wires, new TRUE wires
now default to Enable and new FALSE wires default to Disable. Existing
saved action wires are NEVER silently rewritten; connect RESULT to
replace a conflicting pair, or right-click and edit the existing wire.

Game Object Properties (including when inspecting a target) now exposes
RESULT -> enabled state in the collapsed independent logic-node section.
The same underlying logicNodes[].resultTargets data is used by both
editors. A plain Decoration referenced ONLY by a RESULT binding is
promoted to managed non-colliding Decoration on graph save.
