SIDBOX / CoderGirl IDE — Stage 5.166.68.281026
================================================
WORLD START / SAVE-LOAD: INITIALISE PERSISTENT VISUAL LOGIC

WHAT CHANGED
  Before: independent graphs were only evaluated after a Trigger fired or
  one of its inputs changed inside the Trigger action dispatcher. World
  start, returning from another world, or loading a checkpoint did not
  resolve derived outputs until gameplay later triggered an evaluation.

  Now: the world manager calls a generated world-local
  gameworlditems_sync_logic() once, after objects_init, saved mutable world
  object restore, remote object actions, weather/day-night restoration,
  Spotlight defaults and ring setup. The pass finishes before frame one.

  The initial pass:
    - Calculates all independent graph nodes from restored inputs.
    - Applies every RESULT state binding (0 or 1).
    - Executes deterministic TRUE/FALSE enable/disable target actions,
      including NPCs, same/cross-world Game Objects and Spotlight.
    - Applies authored weather and day/night command choices (if connected).
    - NEVER fires dialogue, Toggle actions or world transitions during
      world entry/reload. These remain normal gameplay Trigger actions.

  No changes to .sbgm, .vsgm, save-slot file layouts, user-owned main.c,
  event node interface or ordinary trigger branch dispatch. No per-frame
  extra scan: this is one evaluation per world activation.

INSTALL
1. Overlay this complete source archive on Stage 5.166.67 IDE source.
2. Rebuild the Qt IDE. Splash: Build: 5.166.68.281026.
3. Regenerate ALL Worlds / Update Game Project, then rebuild the SIDBOX game.
4. Do not replace your hand-maintained main.c.

RECOMMENDED HARDWARE TEST
1. In World1, make the two decorations used by AND/logic1 initially OFF.
   Set RESULT to logictest[2] and connect TRUE/YES -> PLAYER Spotlight
   Enable, FALSE/NO -> PLAYER Spotlight Disable.
2. Start the game. With both switches OFF, derived result and Spotlight
   should be OFF immediately, without pressing any Trigger.
3. Turn on BOTH switches. Spotlight and result must turn ON.
4. Turn ONE switch off, save progress and reload that slot. Both derived
   result and Spotlight must be OFF immediately on resume. No dialogues.
5. Save with BOTH switches ON and reload. Spotlight must be ON immediately.
6. Leave World1 for Forest and return. Current switch states should
   immediately determine the Spotlight and derived result in World1.
7. Put a dialogue on FALSE and a world transition on TRUE in an unrelated
   graph. Entry/reload must NOT show the dialogue or auto-travel.
8. Test regular Trigger gameplay; dialogs, Toggle and explicit travel
   should continue to work exactly as before.
