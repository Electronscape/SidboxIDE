# GamerGirl Stage 4.30 — Adventure Editor visual workflow

**Base:** Stage 4.29. This is an IDE/source update; your existing `.sbgm` projects are preserved.

## What changed

1. **8×16 font wrap:** dialogue text now wraps at 50 characters (400px) within its 416px text region; before it stopped at 39 characters. 16px/20px vertical line stepping is unchanged; choices still have a spacer.
2. **Dialogue skin atlas:** click one of nine frame tiles to open a scrollable visual PPB atlas grid. Picker and generated tables accept cell IDs 0..65535; the runtime rebases the pixel pointer so `gfxbob_t.index` can remain 0 and cells >255 still render. Tile size in pixels is unchanged.
3. **Palette:** foreground text and outline colours are selected from a visible 16×16 palette grid. Outline checkbox retained, with separate palette colour.
4. **NPC Animations:** pick *Idle* and *Talking* first/last frames on the actual NPC PPB sprite atlas. Preview the chosen frame strips; use a slider to adjust timing. NPC BOB frames stay 0..255 (actual `gfxbob_t.index` field is 8-bit).
5. **Dialogue choices:** "Next" is now a dropdown listing existing dialogue nodes plus "Close conversation". "Event / resource" offers game objects by name; choose Enable/Disable/Toggle action. The custom event ID option remains available.
6. **Inventory items:** "Collectable kind" is a dropdown listing *placed* collectables for each kind (1–4). The generated pickup callback still uses `game_adventure_collect(item->kind)`; there is no new collision system.
7. **NPC draw:** new `game_adventure_draw_npcs(camera_x,camera_y)` draws configured NPC sprite BOBs from *generated* world positions. Future generated `maingame.c.txt` excludes NPCs from duplicate ordinary sprite draws and calls the helper once. Update Game Project after moving a placed NPC.

## Important for your hand-edited `main.c`

GamerGirl **will not overwrite** your custom `main.c` — this is intentional.

When upgrading from 4.29, retain your existing `gameadventure_setup()`, `game_adventure_input(...)`, and `game_adventure_draw(...)` calls. In the foreground draw order, after tilemap/world items and before your player sprite, replace the old hard-coded Guardian drawing lines, e.g.:

```c
Guardian[0].drawx = 3048 - camera_x;
Guardian[0].drawy = 144 - camera_y;
gfx_drawbob(&Guardian[0]);
```

with **one** new line:

```c
game_adventure_draw_npcs(camera_x, camera_y);
```

Delete the old manual draw to avoid drawing the NPC twice. The example project generated by Stage 4.30 shows the correct placement.

If your `main.c` defines a custom `on_pickup()` callback and you want automatic inventory collection, it **must** call:

```c
game_adventure_collect(item->kind);
```

That bridge is already present in the generated starter example, but the IDE does not overwrite your callback.

## Installing

- Back up your IDE and game project first.
- Extract the full archive for a complete IDE source checkout, or merge the changed-files archive into the root of your existing Stage 4.29 IDE source tree (preserve relative paths).
- Build the Qt6 IDE locally in Fedora.
- Open your existing `.sbgm`, choose the Adventure Editor, change any settings, save, **Update Game Project**, and rebuild the V1 platformer.
- If a new C runtime helper is not included in your game's existing build list, use the generated build/project files, or replace the runtime helper under `gamehelpers/` as described by the generated helper. Do not rename `TFCard` paths.

## Deliberate limitations

- The inventory mapping is currently by collectable kind (1–4). Several collectables of the same kind map to the same item definition. An individual-instance collectable→item binding is not yet implemented.
- Per-resource named events currently refer to **Game Objects**. Custom callbacks still take numeric event IDs.
- The NPC draw helper uses IDE-generated world positions, regenerated when you move the Sprite and choose Update Game Project. It is not a dynamic pathfinding/movement system.
- The background/foreground ordering remains the same. NPC draw helper draws after the tilemap, before the player, unless you deliberately move the call.
