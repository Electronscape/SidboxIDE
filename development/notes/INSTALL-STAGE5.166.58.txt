STAGE 5.166.58.281026 — GAME OBJECT / VISUAL NODES BOOLEAN EDITOR PARITY

INSTALL
Apply the Stage 5.166.58 hotfix over Stage 5.166.57 IDE source and rebuild IDE.
No game-world or runtime regeneration is necessary solely to install the IDE.
After editing gameplay Boolean links, save the .sbgm design, regenerate worlds,
and rebuild V1 for those new actions to take effect on SIDBOX.

TEST (on a backup world)
1. Open stopLift (Trigger) in Game Object Properties.
2. Find Boolean in Switch, Trigger & Save Checkpoint. It should show Lifty as
   the state source and your existing TRUE and FALSE dialogue selections.
3. Change one of the TRUE/FALSE dialogues, add an object action, reorder it,
   Save, then save the .sbgm world.
4. Open .vsgm and confirm the TRUE/FALSE links are updated. Changing a link
   in Visual Nodes and saving should show in Game Object Properties too.
5. Open Lifty's Properties. In Triggers Reading This Object, the stopLift branch
   should be editable, including source, dialogues and action lists.
6. Change a branch from Lifty, Save, save world, and reopen stopLift and the
   .vsgm: they must all report the same Trigger-owned fields.
7. With an unsaved change, Cancel or Previous/Next -> No must discard it.
8. Create a Trigger with no Boolean: it may choose a source and TRUE/FALSE
   actions directly from its own traditional Properties editor.

SEMANTICS
The branch runs only after its owning Trigger activates, and AFTER that
Trigger's unconditional actions. TRUE = source object ACTIVE; FALSE = INACTIVE.
It is NOT an independent On Enable/On Disable callback on the source object.
The source dropdown must be selected before retaining branch actions/dialogue.
Dialogue text and advanced choices are still authored in the Adventure Editor
(or in the Visual Nodes dialogue card); this section edits dialogue REFERENCES.

SAFETY / LIMITATIONS
The existing .sbgm schema, .vsgm layout, runtime, .map and main.c are unchanged.
Full Qt6 compilation and GUI interaction cannot be verified in this environment.
Keep your backup and test the two-way Save/Cancel behaviour on the desktop.
