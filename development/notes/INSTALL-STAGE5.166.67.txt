SIDBOX / CoderGirl IDE — Stage 5.166.67.281026
PLAYER graph command targets, weather/daylight controls and deferred world transitions

INSTALL
1. Back up your IDE source and game design worlds.
2. Replace Stage 5.166.66 with this entire source tree, or apply the following
   modified files at their existing relative paths:
     gamevisualnodes.cpp
     gamedesigner.cpp
     gamedesigner_export.cpp
     idelibs/codehelpers/game/gameworlds.rulec
     idelibs/codehelpers/game/gameworlds.ruleh
     splashscreenwidget.cpp
3. Rebuild the Qt IDE. Splash build must read 5.166.67.281026.
4. In your game project, use Update Game Project / Regenerate All Worlds to
   rebuild gamehelpers/gameworlditems.c, gameworlds.c and gameworlds.h.
5. Rebuild the game for V1 SIDBOX. Your hand-owned main.c is NOT modified.

PLAYER TREE — Visual Nodes
In a Trigger or independent Logic TRUE/FALSE output, drag into the canvas and
choose the PLAYER tree, then select:
  Spotlight                 (Enable / Disable / Toggle; FALSE defaults Disable)
  Weather & Effects:
     Clear / Rain / Snow / Thunderstorm
  Time of Day:
     Daylight / Night / Resume Day/Night Cycle
  World Transitions:
     Go to <authored sibling world> (default Player Start)
Existing Goto World world objects are still shown in PLAYER when browsing
unconnected cards and retain their original physical-interaction semantics.

Weather/time/world commands use the existing action JSON shape and must carry
'action: enable'. This means RUN COMMAND, not enable that world's active flag.
Spotlight retains actual Enable/Disable/Toggle semantics. Right-click a green
or red action wire to remove it. Other command wires cannot be changed to
Disable/Toggle, since those operations would not make sense. The same valid
PLAYER targets can be viewed/edited in the Game Object Properties action lists.

World change uses gameworlds_request_at(destination,"default") during the
branch; the manager performs the transition later at its safe frame boundary.
The selected name must exist as a sibling .sbgm and map to the same runtime
world ID as the Goto World property editor. A removed destination fails
export validation rather than silently producing a nonfunctional action.
World start is the destination's DEFAULT Player Start; selecting a named
Player Start is not yet provided by this initial PLAYER graph action stage.

Weather changes only the loaded world's live weather mode, without changing
its saved designer presets. Rain/snow are visible even if the world originally
had zero precipitation density. Storm enables the existing lightning overlay
when the world configured no lightning effect. Clearing weather stops current
precipitation/flash, retaining tint/time settings independently. Weather
returns to the world preset when leaving and returning.

Daylight suppresses tint, Night uses that world's configured tint (or 60%
strength if it was disabled), Cycle resumes the world's authored day/fade/night
cycle, starting at saved cycle progress if available, otherwise morning. The
per-world cycle pause/restore introduced in Stage 5.162 is not replaced.
Day/night actions still dispatch configured day/night object/NPC actions when
changing phase. Re-entry restores each world's own authored effect settings.

COMPATIBILITY / SAFETY
- .sbgm schema unchanged: command ID occupies a pre-existing target objectId.
- .vsgm schema unchanged: only card positions/camera remain there.
- Saved slot / .map / palette / PPB formats unchanged.
- Independent Boolean, AND, OR, NOT and RESULT nodes continue reading/setting
  only real local Game Object active states. PLAYER action cards have no state
  output and cannot be bound directly to RESULT.
- Existing NPC and remote-world Game Object logic commands are untouched.
- No changes to owner-maintained main.c.
