SIDBOX / CoderGirl IDE - Stage 5.166.115.291026
Breakable events can now feed independent Visual Node logic.

Source baseline: Stage 5.166.114.291026.

What changed:
- Breakable ON HIT and ON DESTROY gold ports can create a Boolean/AND/OR/NOT gate.
- The gate is owned by the breakable: a real one-frame event input, not its persistent active STATE.
- Add the other inputs by dragging the teal STATE ports onto the numbered gate inputs.
- TRUE/FALSE actions can be set to Enable, Disable, or Toggle as previously.
- ON HIT and ON DESTROY are evaluated from the distinct existing runtime event flags.
- Runtime emits a named one-frame event even if it has no ordinary direct event actions.
- Properties, .sbgm serialization, cross-world resource copying, and graph deletion understand these inputs.
- No save-game payload changes; save fingerprint logic unchanged.

IMPORTANT: user project is not modified by this source update.
For the bonkCollect example:
  1. Remove the direct bonkCollect ON DESTROY -> Spotlight action wire.
  2. Remove the old Springer-owned AND -> bonkCollect Enable wire (if no longer wanted).
  3. Drag bonkCollect gold ON DESTROY to empty canvas -> Logic -> AND.
     This creates a NEW gate owned by bonkCollect, initially with one event input.
  4. Drag springer1 teal STATE to INPUT 2 and logictest[0] teal STATE to INPUT 3.
  5. Connect AND TRUE to Spotlight and set the action wire to Toggle.
  6. Save .sbgm, export/rebuild the game, test with states enabled/disabled.
  Do not attempt to insert an ON DESTROY event into the old Springer-owned gate.
  Event-driven gates deliberately belong to the event source object.

Expected: destruction toggles Spotlight once ONLY if Springer and logictest[0] are active at destruction. Otherwise it does nothing. A later state change alone must not replay the destruction pulse.
