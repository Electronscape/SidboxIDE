CODERGIRL / SIDBOX IDE -- Stage 5.166.22.271026
Map fill, atlas flag picker, smooth defeat fade, viewport-fit defeat and checkpoint respawn

BASE: Stage 5.166.21

INSTALL
1. Back up your IDE sources and project, then extract the DROPIN ZIP over the
   IDE Stage 5.166.21 source tree. Or use the complete FULL.tar.gz archive.
2. Rebuild the IDE on Fedora and confirm Build: 5.166.22.271026.
3. In Quests > World Map Designer, choose a project PPB and atlas tile, then
   use 'Fill empty cells' for water/grass or 'Flood fill connected area' for
   a bounded area. Select a World flag and click 'Pick from atlas...'.
4. In Quests > Defeat Screen, review font and skin selections. The live defeat
   display no longer shows CHOOSE SAVE TO RELOAD; all UI sits inside the
   Quest Journal HUD-aware viewport.
5. Save authoring changes, select Update ALL Worlds / Update Game Project,
   rebuild the V1 .app and transfer it to SIDBOX. The Adventure and World
   manager generated runtime has changed, so world regeneration is REQUIRED.
6. Test Start Game (no checkpoint) -> defeat -> FIRE1 fresh restart.
   Test Start Game -> checkpoint -> defeat -> selected slot restore.
   Test Title Screen Load Game -> defeat -> saved slot restore.
   Especially test same-world save/restore and an arrival in another world.

KEY CHANGES
- Map flags now have an actual PPB popup cell selector (same shared picker
  already used for nine-slice frame tiles), with 2x2 bounds validation.
- Painter has fill-empty-background action and nonrecursive connected-region
  flood-fill mode; right-click flood-fill erases a connected region.
- Death uses a uniform indexed-palette fade, not a mosaic mask.
- Defeat heading, choices and footer now derive from HUD-safe viewport; the
  redundant CHOOSE SAVE TO RELOAD heading was removed.
- Death screen offers slot loads only when player has loaded from title or
  successfully saved a checkpoint in this run. Without a save in this run,
  FIRE1 attempts a fresh restart from a transient initial gameplay snapshot.
- The initial snapshot is allocated only with the Defeat Screen enabled,
  before the first checkpoint and only once; it is freed on successful save.
  Allocation is bounded by the existing 256 KiB save-record maximum. This
  extra DYNAMIC heap allocation is not the V1 statically linked budget bar.
  If the initial snapshot cannot be captured, the death menu reports RESTART
  UNAVAILABLE instead of silently pretending recovery worked.
- Defeat recovery reloads the world at the safe update boundary. The
  manager now restores live physics X/Y/facing from the checkpoint even on a
  same-world load. Generated maingame.c.txt also detects reloads of the same
  world, but user-owned main.c is NOT modified.
- Existing slot banking, TFCard save format, quest progress and direct
  authored gameworlds_reload_request() API remain compatible.

CAUTION
No automatic modifications to owner-maintained main.c, existing projects,
PPB artwork, TFCard save slots or quest definitions. This stage adds the
session initial snapshot (potential dynamic RAM up to 256 KiB before first
checkpoint). Monitor actual heap headroom on memory-constrained game builds.
