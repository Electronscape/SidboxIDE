Stage 5.166.61.281026 - Controllable Decoration Sprites
==========================================================
Base: Stage 5.166.60.281026

What changed
------------
- Ordinary placed sprite resources (the existing default "decoration" type)
  appear in Visual Nodes under Game Objects > Decoration.
- The game-resource tree labels ordinary sprites [decoration] and offers
  navigation to them through Game Objects (the actual sprite is not copied).
- Connect a Trigger or an independent logic TRUE/FALSE action to a Decoration
  and choose Enable / Disable / Toggle. On Save Graph + World, the IDE
  promotes that particular referenced decoration to a managed visual-only
  Game Object, "decoration_object", retaining its original UUID and placement.
- The editor also offers "Decoration (enable / disable / toggle)" explicitly
  in Game Object Properties for people working without Visual Nodes.
- Managed decorations use gameworlditems state, generated GAME_OBJECT_DECORATION
  type, the shared draw path and the existing New Game, save/load, cross-world
  state reset and action dispatch. They never collide with the player.
- The player resource (typically named "player") is not offered as ordinary
  decoration in Visual Nodes; NPC sprites remain under the NPC category.
- Unconnected decoration cards DO NOT change existing scenery rendering.
- Existing non-managed scenery, .map files, and .vsgm format are unchanged.

Limitations and safeguards
--------------------------
- A logic-controlled decoration currently requires a PPB sprite at 100% scale.
  Invalid assets are refused with a clear Save Graph + World error.
- This stage targets straightforward visibility toggles. Decorations with
  special scenery-only rendering (custom patterned alpha fade, etc.) should
  be checked before using managed visibility; drawing them via gameworlditems
  may differ from their previous standalone scenery path.
- No automatic player conversion. User-owned main.c is NEVER overwritten.
- The new managed type is an opt-in .sbgm change when linked. Existing designs
  remain compatible. A .sbgm.vsgm-backup is created by Visual Nodes before
  rewriting game logic, following the existing safety workflow.

Installation
------------
1. Apply hotfix over the Stage 5.166.60 IDE source, or install the complete IDE.
2. Rebuild the IDE and check splash build 5.166.61.281026.
3. Open a backup copy of the world and its Visual Nodes .vsgm.
4. Right-click empty canvas, expand Game Objects > Decoration; place your
   red, green and blue sprite nodes.
5. Connect each from a Trigger / TRUE / FALSE output; choose Enable first,
   then right-click the wire to switch to Disable or Toggle.
6. Save Graph + World. Reopen the .sbgm; each linked visual should now have
   Game Object type "Decoration (enable / disable / toggle)".
7. Run Update ALL Worlds / Update Game Project to refresh gameworlditems and
   gameworldobjects, then rebuild V1.
8. On SIDBOX: verify visibility changes, absence of collision, save/load and
   New Game reset of decoration visibility.
