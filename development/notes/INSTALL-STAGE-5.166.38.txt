SIDBOX CoderGirl IDE Stage 5.166.38.271026
Fresh New Game: reset collected pickups in EVERY world

Apply this HOTFIX over Stage 5.166.37 sources, or use the complete
Stage 5.166.38 source archive. Rebuild the IDE and verify the splash
screen shows Build: 5.166.38.271026.

1. Open The Tiny Red Riot game project in the updated IDE.
2. Run Update ALL Worlds / Update Game Project. This must regenerate
   per-world gameworlditems.c and gameadventure.c for ALL worlds.
3. Rebuild the V1 .app and copy the app as usual. Existing .map files
   remain unchanged on TFCard and are still loaded in the same way.
4. Test: collect a persistent item in World1; visit Forest; collect an item;
   die; FIRE2 to title; choose New Game; revisit both worlds. Both pickups
   must reappear (unless their authored default is initially inactive).
5. Separately test Load Game: save after collecting an item; die; return
   to title; Load Game from the saved slot. The saved collected items must
   remain collected, because saved progression is restored intentionally.

ROOT CAUSE
The title reset cleared cg_world_snapshot_valid, but it forgot the
independent cg_pickup_permanently_collected[] flags. World reinitialisation
then hid pickups despite starting a new session.

FIX
- gameworlditems.rulec now zeroes permanent pickup flags and saved pickup,
  object and reward state when the world manager resets a new session.
- Handles worlds with pickups and no managed platforms.
- gameadventure.rulec also clears its saved story payload on the same reset,
  not just its validity marker.
- Load Game still imports the full saved world and Adventure data after
  the reset, preserving checkpoint semantics and save-file compatibility.

NOT CHANGED
- .map format / .map paths / TFCard deployment
- hand-maintained main.c and generated maingame.c.txt
- save-file encoding/version
- Title selection, death/return, named spawn, idle reset, game physics

  title New/Load, 5.166.36 title input latch, 5.166.37 rules refactor,
