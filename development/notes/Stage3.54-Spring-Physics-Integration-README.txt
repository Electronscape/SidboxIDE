GAMERGIRL STAGE 3.54 — SLIDY SPRINGS FOLLOW REGION PHYSICS
=========================================================
Base: Stage 3.53 large tilemaps, including Stage 3.52 source ownership.

WHY
---
Previously, a spring with "Slidy kickback" maintained its own sideways
spring_x100 velocity inside gameworldobjects.c. It always decayed by 6%
per frame in air and 14% on ground, even inside ICE, WATER or SPACE zones.
That fought the tilemap player's separately configured physics drag.

NEW BEHAVIOUR
-------------
With the OPTIONAL tilemap-player binding below, a Slidy spring sends its
sideways kick into game_tile_player_t.force_vx100 (same channel as
apply_force()). The existing tilemap physics engine handles movement,
subpixel accumulation, wall blocking and damping from the active preset:

  Normal     12% horizontal external-force drag per physics frame
  Ice         2%
  Water      18%
  Slow       18%
  Space       0%
  Floating    4%
  Jetpack     6%

The sideways kick adds to existing horizontal external momentum (subject
to the existing +/-32 px/frame external-force cap), rather than clearing it.
Note: the editor permits +/-40 for spring side-launch; bound Slidy force
uses the same +/-32 safety cap as apply_force(), while OFF/non-Slidy
retains the original launch range.
The spring's vertical launch, touch/landing rules, optional jump boost, and
sound triggers do not change. Normal non-slidy springs remain unchanged.

CRITICAL ONE-LINE UPDATE FOR AN EXISTING USER-OWNED main.c
--------------------------------------------------------
In the existing block where you bind world_player to player_physics, add:

    world_player.spring_force_vx100 = &player_physics.force_vx100;

For context the block should contain:

    world_player.x100 = &player_physics.x100;
    world_player.y100 = &player_physics.y100;
    world_player.vy100 = &player_physics.vy100;
    world_player.spring_force_vx100 = &player_physics.force_vx100; // NEW
    world_player.on_ground = &player_physics.on_ground;

YOUR `main.c` WILL NOT BE OVERWRITTEN. Stage 3.52 user ownership remains in
force. The generated maingame.c.txt includes this new binding, and the
`gameworlditems.txt` documentation explains it.

If you do not add the binding, the spring still works (backward compatibility),
but its Slidy checkbox uses the old 6%/14% hard-coded friction and won't
honour ICE/WATER/SPACE. Older standalone games without a tilemap player are
unaffected. The adapter must remain zero-initialized/persistent as before.

INSTALLATION
------------
1. Back up IDE and game as usual.
2. Apply Stage 3.54 source changes to Stage 3.53 and rebuild the IDE.
3. In GamerGirl, select Update Game Project. Update gamehelpers/gameworldobjects.c
   and gamehelpers/gameworldobjects.h; regenerate gameworlditems examples.
4. Edit your USER-owned main.c and add the SINGLE pointer binding above.
5. Rebuild Platformer3 and test a Slidy spring adjacent to ICE, normal, and
   WATER or SPACE areas, particularly the transitions between regions.
