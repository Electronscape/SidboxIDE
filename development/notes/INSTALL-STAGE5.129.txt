CoderGirl Stage 5.129.251026 - Inventory drops use Player Animation FOOT X/Y

IMPORTANT: This corrects Stage 5.128's origin. DO NOT apply the earlier
"Stage5.128-Main-Hitbox-Hotfix.patch" to solve item placement. It changes the
input hitbox arguments and does not read the Player Animation Foot anchor.
If you already applied that patch, do not add the hitbox offsets a second time.
Stage 5.129 does not require any main.c edit.

INSTALL
1. Extract Stage 5.129 DROPIN over the Stage 5.128 IDE SOURCE ROOT, keeping paths.
2. Rebuild the IDE (existing minimum Qt6 6.5; no new Qt APIs in this stage).
3. Open Player -> Create/Edit Animations, check the saved FOOT X/Y in
   gameanimations/player_anim.sbanim. Save Animations and agree to regenerate
   gameanimations/player_anim.h to expose the FOOT_X and FOOT_Y macros.
4. In Game Designer click Update Game Project for each relevant world. This
   regenerates gameadventure.c, gameadventureruntime.c/.h and gameworlds.c/.h
   with the new foot-anchor hookup. (The world manager and adventure module
   are generated in the gamehelpers area.)
5. Rebuild the SIDBOX GAME. Existing hand-edited main.c remains untouched.

HOW IT WORKS
- Foot X/Y are SPRITE-LOCAL offsets from the sprite top-left, saved by the
  Player Animation editor; they are not collision hitbox X/Y offsets.
- World runtime reads the LIVE player physics sprite origin through the
  existing gameworlds_bind_player_physics() binding. The callback never writes
  x100/y100, hitbox, or any movement/collision state.
- Item X, facing RIGHT: sprite X + Foot X + hitbox width + 8.
- Item X, facing LEFT:  sprite X + Foot X - hitbox width - 16 - 8.
- Item Y: sprite Y + Foot Y - hitbox height/2 - 8, centring the 16px icon
  halfway up the hitbox from the foot anchor. It then falls as in Stage 5.128.
- The widths/heights are taken from the saved .sbanim unless the shared player
  profile explicitly overrides the hitbox. Use accurate Foot X/Y for the
  direction-independent sprite anchor; the left/right direction controls the
  horizontal offset.
- Existing Adventure input / NPC overlap and tile physics are not changed.
- If the game does not bind player physics, the runtime retains the older
  rectangle-based placement rather than causing an unbound-pointer failure.
- World changes register the same shared player foot settings again.
- Dropped item save structure and persisted drops remain unchanged.
