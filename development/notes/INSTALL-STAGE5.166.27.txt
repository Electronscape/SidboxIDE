SIDBOX / CoderGirl IDE - Stage 5.166.27.271026 (27 October 2026)
================================================================
BASE: Stage 5.166.26.271026

CORRECTIONS

1. New Game after a death without a save no longer trusts the newly opened
   title screen's selected world (nor worlds[0], which is typically alphabetical).
   It decodes the existing verified fresh-start snapshot, reads that snapshot's
   validated world index, and starts exactly that saved original world. A Title
   Load Game action still loads the world and position stored in the selected
   TFCard slot, unchanged. This fixes arriving in Forest instead of World1
   after a no-save death, without changing owner-maintained main.c.

2. World Map boundary now controls the thick runtime surround as well as the
   actual 5-pixel frame. Previously, the huge background/margin rectangle was
   painted using the Quest Journal background palette index, which could show
   as a thick garish green region regardless of the World Map colour choice.
   The header/footer captions retain the journal's legible fill inset inside
   the selected frame, and the whole map remains HUD-aware.

3. Map generator rejects a template missing the boundary and flashing flag
   colour placeholders, instead of silently ignoring the selected colours.
   The saved values remain world-map.json borderColour/flagFlashColour (indices
   0..255) and are embedded into each regenerated world's gameadventure.c.

IMPORTANT: Indexed colours use the ACTIVE RUNTIME WORLD palette. If a custom
preview .pal/.ppb has a different CLUT than the active game world, the exact
RGB shown by the IDE preview can differ from the SIDBOX runtime; selecting
an index available in the game's runtime palette is recommended. No CLUT
resource is modified by this change.

INSTALL
1. Back up your IDE and game project.
2. Install full Stage 5.166.27 source OR apply the hotfix over 5.166.26.
3. Rebuild the IDE and verify splash version 5.166.27.271026.
4. World Map Designer: choose desired World Map outer boundary colour; Save.
5. Update ALL Worlds / Update Game Project; rebuild V1 game and refresh files
   on the TFCard as appropriate.
6. Test Start Game -> death without checkpoint -> title -> New Game. You
   should return to your original starting world, not the last visited level.
   Test direct-background refresh and Load Game with a saved checkpoint too.
7. Inspect generated worlds/<world>/gamehelpers/gameadventure.c to confirm
   game_adventure_world_map_boundary(<selected index>u) if the colour seems
   unchanged. Old published worlds need regenerating; merely rebuilding main.c
   will not update the per-world generated map style.
