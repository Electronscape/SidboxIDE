GamerGirl Stage 3.55 — Bezier collision stamps + experimental loop tracks
=======================================================================
Based on the full Stage 3.54 IDE. Make a backup of your project and user-owned
main.c. Not a firmware patch. Qt editor compilation and physical SIDBOX runs
must still be done on Fedora / real hardware.

CHANGED FILES:
  gametilemap.cpp                        editor, save/export, loop controls
  gametilemap.h                          design-time loop struct
  gamedesigner.cpp                       generated maingame.c.txt guide
  idelibs/codehelpers/game/tilemap.c     bigger slope step-up, guided loop
  idelibs/codehelpers/game/tilemap.h     optional loop type and physics state
  idelibs/docs/cheatsheet.json           F8 Guide 53

1. Backup the game and rebuild this IDE (Qt6 is not installed in our test env).
2. Open Tilemap Editor > Collision Stamps. Select or create a slope stamp.
   Move its two endpoints vertically as needed, then click Generate Bezier Curve.
   Adjust both control handles; the LIVE preview shows the curve. Apply to
   bake a maximum of 128 short, editable segments into the existing v4 shape.
   All existing placements that reference that stamp update together.
3. To try a complete loop, go to Loop Tracks > Add Loop. Set the centre in
   WORLD PIXELS, radius, and minimum entry speed (pixels per frame).
   A dashed blue circle, red surface-normal ticks and yellow bottom entrance appear when Show collisions
   is enabled. Its bottom entrance must coincide with walkable artwork/ground;
   a curved collision-stamp ramp can be placed as an approach (green in sketch).
   Loops attach in EITHER direction if the player is on ground and has enough
   horizontal speed. Gravity slows upward motion and can release the player.
   The curve is not drawn in-game; provide your own atlas artwork.
4. Save the map, Update Game Project, refresh gametilemap.c/.h, rebuild game.
   Stage 3.52 OWNER: user remains intact. Nothing requires a main.c edit if
   the player already uses generated game_level1 and game_tile_player_run().
   maingame.c.txt explains optional game_tile_player_on_loop() usage.
5. For an easy test, use a clean flat test level, not your irreplaceable map.
   Set loop centre at world (128,116), radius 60; bottom entrance is (128,176).
   Put solid floor with its TOP at y=176, approach at speed >4 px/frame using
   the icy kick spring, and experiment with slowing the kick to cause release.
   For an 8x8 player, ensure there are no nearby competing collision zones.
6. Test: ordinary linear/point slopes and springs, low-speed entry, high-speed
   loop clockwise/anticlockwise, failing off high arc, entering/exiting zones,
   editing/saving/reloading .sbgm, external .map and embedded C builds, undo,
   multiple loops, and large maps.

LIMITATIONS / CAUTION
- This is a first CIRCULAR TRACK implementation, NOT yet a freely editable
  loop spline matching every bend of the drawing. Both directions share a
  single bottom entry/exit marker. Start/end cannot be separated yet.
- Curved stamps remain x-monotonic (one height per x). Do not use them for the
  inverted loop ceiling; use the Loop Tracks tab for this.
- The loop currently guides only game_tile_player_t, not placed moving objects
  or rolling boulders. Generic rolling-object track collision is future work.
- While attached to a loop, the player bypasses regular tile SOLID collision;
  do not place unintentional solids or hazards through the circle. Hazard and
  custom-zone callbacks do continue while attached. Sprite drawing remains
  upright; gfxbob_t does not provide sprite rotation.
- Jumping off an attached loop is not separately implemented yet; this
  experimental mode guides the player until release or a full revolution.
- Do not expect 100% conservation of physical kinetic energy: this remains
  arcade gameplay using physics-preset drag, a fixed-point sine lookup,
  and an approximate circular contact threshold.
- Project .sbgm gains optional loopTracks metadata; the external SBMP .map
  binary format is UNCHANGED because loop definitions live in level1.c.
- The full Qt GUI has not been compiled here; check your IDE compiler output.

HOST-TESTED (GCC + address/undefined sanitizers):
- Positive and negative entries complete full 360-degree circuits.
- 2:1 steep slope follows uphill without sticking to a side wall.
- Previous Stage 3.54 icy/normal/water/space spring force tests passed.
- Low-speed loop contact releases player above floor with tangent velocity.
- ENTERED/INSIDE/EXITED custom-zone callbacks fire during track travel.
- C helper compiled with -Werror; no STM32 firmware modified.
