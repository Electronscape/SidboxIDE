CoderGirl IDE Stage 5.164.5 (27 October 2026)
Game-local TFCard saves, with legacy save loading
================================================

USER REQUEST
Place game save files alongside the launched game rather than in the
TFCard-root /CGSAVES directory.

CHANGE
idelibs/codehelpers/game/gameworlds.rulec:
- New saves use a relative FAT 8.3 filename, e.g. 12ABCD0A.SAV and
  12ABCD0B.SAV (project key, slot 0-9, copy A or B).
- These filenames are resolved using the SIDBOX filesystem's current
  working directory. When the launcher sets that directory to the app's
  folder, the files are directly alongside the .app.
- The two independent save banks, checksums, layout/version validation,
  inventory, world state and player position are unchanged.
- The Load Game menu searches game-local banks first, then falls back to
  valid legacy /CGSAVES banks when a slot has no valid local save.
- Saving creates/updates ONLY game-local files; it never rewrites or deletes
  a legacy save. Legacy saves are therefore safe to keep as backups.
- The game-local directory is not created by this code; it must exist.
- The fallback is read-only and occurs per slot. If local banks are both
  invalid, a valid legacy save can still be loaded.

LIMITATION
The published SIDBOX SDK exposes sfgetcwd/sfchdir (working directory)
but no direct API to query the directory of the currently executing .app.
This source uses relative paths, NOT an invented application-path API.
For the result to be literally alongside the .app, SIDBOX must launch it
with that folder as the TFCard current working directory. Check on real
hardware with a .app located in a subfolder. If firmware leaves CWD at
root, the .SAV files will be written to root instead. No firmware source
was supplied to verify that behaviour.

INSTALL OVER STAGE 5.164.4
1. Back up the working CoderGirl IDE source and your Platformer3 project.
2. Extract the drop-in ZIP over the IDE source root (preserve paths).
3. Rebuild the Qt6 IDE; splash: Build: 5.164.5.271026.
4. Open Platformer3, use Update Game Project / Update ALL Worlds to
   regenerate gamehelpers/gameworlds.c from the changed rule template.
5. Rebuild the game; keep your hand-maintained main.c untouched.
6. On SIDBOX, launch the .app from its intended TFCard folder; visit a
   checkpoint, save, then inspect the TFCard to confirm the .SAV files
   were written beside the app.
7. Reboot and load that same slot. Inventory, saved world and player XY
   should remain unchanged from the working 5.164.4 behaviour.
8. Your previous saves under /CGSAVES remain readable; they are NOT moved
   or deleted. After creating a new save, new local files take precedence.
