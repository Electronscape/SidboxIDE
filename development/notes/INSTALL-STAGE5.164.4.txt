CoderGirl IDE Stage 5.164.4 (26 October 2026)
Save-point resume and Load Game text styling fixes
=================================================

BUGS REPORTED ON REAL SIDBOX
- Load Game list ignored the configured title-entry foreground and text outline.
- A saved game selected after reboot could start from the ordinary Player Start
  or the project's default world instead of resuming the checkpoint.

WHAT CHANGED
1) idelibs/codehelpers/game/gametitle-runtime.rulec
   Load Game heading, slots and footer inherit the Load Game menu entry's
   foreground, outlined switch, outline colour and outline thickness.
   Glyph scale is kept small enough to fit ten slots on the 480x320 screen.
   The normal menu selector is used for the active slot. Loading also queues
   the selected slot in the world manager before returning to hand-owned main.c.
2) idelibs/codehelpers/game/gameworlds.rulec
   Initial gameworlds_start() honours an already-selected title save even if
   older user-owned main.c starts a hard-coded default world.
   Saving reads the LIVE player coordinates and facing, not the world start.
   If there is no current physics player it REFUSES the save rather than
   overwriting the previous valid slot with incorrect coordinates.
3) idelibs/codehelpers/game/tilemap.c / tilemap.h
   game_tile_player_start() records the live physics player, even in older
   user-owned main.c that does not call gameworlds_bind_player_physics().
4) gamedesigner.cpp
   Detects outdated gametilemap.c/.h in game projects and offers a backed-up
   upgrade when exporting; do not skip this upgrade for checkpoint saves.
5) splashscreenwidget.cpp
   Build: 5.164.4.261026

INSTALL OVER STAGE 5.164.3
1. Back up your currently working IDE source and Platformer3 project.
2. Unzip the Stage 5.164.4 drop-in at the IDE source root, retaining paths.
3. Rebuild the Qt6 IDE and check splash says 5.164.4.261026.
4. Open the game and run Update ALL Worlds / Update Game Project to regenerate
   gamehelpers/gameworlds.c and gamehelpers/gametitle.c.
5. IMPORTANT: accept the Upgrade Tilemap Helpers prompt, which backs up your
   current gamehelpers/gametilemap.c/.h and copies the updated helpers.
   Check the backups if you have edited those helpers yourself.
6. Build the game. Your hand-maintained main.c should not be replaced.
7. Create a NEW save at the checkpoint while the player is away from its
   starting coordinates. Reboot, open Load Game, select the correct slot,
   and verify world, XY/facing, inventory and event state.

A save written by 5.164.3 may already contain the wrong (default) position:
this update cannot reconstruct position missing from that old file. Save again
at the checkpoint after installing the new runtime; existing saves stay on TFCard.

TESTED IN THIS PACKAGE
- Native C save/load and two-bank corruption recovery.
- Native C title-marker return to saved world even when initial main requests
  a different default world.
- Native C exact player XY/facing save/restore, and rejection when no live
  player can be found.
- Native tilemap.c registration of the live game_tile_player_t.
- 16 world-rule configuration checks; two-world callback declarations.
- Inventory checkpoint interaction and selector source checks.
- C syntax check of tilemap.c.

NOT YET TESTED: Qt6 executable, your exact CURRENT user-owned main.c,
full ARM game build or hardware TFCard roundtrip. Please report if the new
live-position capture upgrade prompt did not appear or the game still resumes
at the initial Player Start.

This update does NOT change the TFCard save-file format, file names, slot
count, bank switching, game day/night behaviour or world-transition rules.
