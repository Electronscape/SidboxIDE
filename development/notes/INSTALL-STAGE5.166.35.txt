SIDBOX CoderGirl IDE Stage 5.166.35.271026
TITLE SESSION + HURT STATE RESET (V1)
==========================================

WHY
----
Stage 5.166.34 treated a previous initial-run snapshot as the starting
world/position after dying. It could override the title menu's configured
Start Game target, especially after visiting Forest. The separate
loaded-save branch only cleared parts of the old playthrough.

Stage 5.166.35 uses one clean reset for both title choices. New Game
follows the selected title menu's world + NAMED Player Start. Load Game
first discards the old session, then fully decodes the chosen TFCard slot,
including its saved world and player position.

The runtime manager also clears the bound world-player Hurt timer/animation,
Hurt flash, spring motion, and damage flags on a title restart AND an in-game
Defeat Screen FIRE1 reload. The generated maingame.c.txt reinitialises
its player animation on reload_revision changes, even in the same world.
No saved-slot disk format was changed.

INSTALL THE IDE
---------------
1. Apply the hotfix over Stage 5.166.34, or install the complete IDE.
2. Rebuild the IDE (splash: Build: 5.166.35.271026).
3. Open your game; use Update ALL Worlds / Update Game Project.
4. Rebuild the V1 game.

IMPORTANT: USER-OWNED main.c
----------------------------
Existing hand-owned main.c is NEVER overwritten by the IDE. The
uploaded game main.c had two separate bugs:
  a) It ran gametitle_run() but then called gameworlds_start(WORLDLEVEL),
     ignoring title_world and title_start (including chosen named spawn).
  b) It detected only world NAME changes in the frame loop, ignoring the
     reload revision. Same-world title/save reloads therefore skipped
     the normal rebind and left player animation/motion in an old state.

A COMPLETE corrected main.c, based on the user's supplied 27-Oct-2026
game archive, is distributed separately as main-Stage-5.166.35.c.
Copy it to the game project as main.c ONLY after preserving a backup and
reviewing any new edits made since that particular uploaded archive.
Do not copy it into the IDE source tree.

The IDE's regenerated maingame.c.txt also includes the correct startup
and reload-revision patterns with comments under Stage 5.166.35.
