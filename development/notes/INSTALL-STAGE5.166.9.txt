SIDBOX CoderGirl Stage 5.166.9 | Quest Journal true 2x2 tile icons + compiler fix
27 October 2026

INSTALL
1. Extract CoderGirl-Stage5.166.9-271026-DROPIN.zip over the Stage 5.166.8 source tree.
2. Rebuild the Qt6 desktop IDE. Verify splash: Build: 5.166.9.271026.
3. Open Quests > Journal Appearance. The five icon slots now have a 2x2 tiles option.
4. Select a Journal Frame atlas with Tile Size 8 px. Enable 2x2 for an icon; choose
   its TL, TR, BL, BR tiles separately. You can still use a single tile per icon.
5. Save the journal design. Run Update ALL Worlds / Update Game Project and accept
   regenerated Adventure runtime/source helpers, then rebuild/transfer your game.
6. Test on SIDBOX, especially active/completed icon mosaics and description scrolling.

CHANGES
- Resolved generated C compiler error: ga_answer_rows() now has a proper
  forward declaration before the quest-input function calls it.
- Journal Appearance has single-tile / native 2x2 mode per icon slot.
- 2x2 mosaics combine four selected 8x8 atlas cells at scale=100 (real 16x16).
- X/Y flipping applies to the composite as a whole, including tile order.
- Single-tile icons are also drawn at native resolution, no implicit upscale.
- Journal preview matches the runtime icon mode and tile arrangement.
- Description scroll calculations now use the same wrap width as the renderer.
- Old appearance files with version 1 remain readable: icon2x2/iconParts absent
  means existing icon slots stay in single-tile mode.

COMPATIBILITY
- No changes to the existing quest manager, quest discovery, save layout,
  TFCard files, hand-maintained main.c, or quest IDs.
- 2x2 mode is designed for Tile Size = 8 px. The generator rejects a 2x2
  selection made with another tile size instead of silently rescaling art.
- Old single-tile icon settings are preserved when opening/saving the designer.

VALIDATION
- Compiled/ran a native C test of real four-bob drawing and no scaling.
- Native touch/joystick and quest manager regression tests passed.
- Rendered runtime C compiles against actual bundled SIDBOX apis.h headers.
- The SDK's existing API-address checks produce two -Waddress warnings; there
  are no new source errors (tested with -Wno-error=address).
- Full Qt6 GUI build and physical SIDBOX validation remain outstanding.
