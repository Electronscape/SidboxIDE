SIDBOX / GamerGirl Stage 3.46 — Dedicated Tile Atlases
=======================================================
Base: Stage 3.45 (Escape cancels temporary region stamp)
Scope: Game Designer desktop IDE and V1 game code generation only.
No firmware changes. No new .map/.sbgm version, tilemap helper or physics change.

WHAT'S NEW
----------
1. Game Resources now has a dedicated "Tile Atlases" group, after Sprites.
   Add Tile Atlas... accepts indexed SIDBOX .ppb resources (or drop PPB onto
   the Tile Atlases tree root). The registered image is never placed on the
   game canvas and is never emitted as a sprite/draw call.
2. Tilemap Editor's Tile Atlas dropdown now chooses from Tile Atlases,
   while preserving the active older sprite-hosted atlas for legacy designs.
   Tile IDs and the tilemap's atlasPath continue to be stored as before.
3. For a legacy decorative PPB atlas-holder sprite, right-click and choose
   "Move to Tile Atlases (stop drawing)...". Confirmation is required.
   The PPB file/path and current tilemap reference are retained. This removes
   the sprite from generated game drawing after Update Project. If custom
   game C references that sprite symbol, update your game C accordingly.
   A reverse "Move to Sprites" action is available.
4. Save/reopen stores Tile Atlases in the ordinary .sbgm resource list
   (kind: tileatlas). Older .sbgm files still load unchanged.
5. V1 gameassets generation includes only the current map's selected atlas
   from Tile Atlases, not every atlas in the bank. The matching PPB bytes
   are loaded once (or embedded if that generation mode is chosen), exposed
   through gameassets_find_ppb(), and borrowed by the existing tilemap atlas
   loader after its checksum verification. This avoids a redundant atlas
   allocation without creating a sprite. SD-only fallback remains available.
6. Build Shared CLUT includes the selected Tile Atlas PPB in foreground
   colours despite its absence from the canvas. The active tile atlas can
   also have its PPB path replaced, which relinks the map's atlasPath.
7. F8 -> Game Engines -> Advanced Platformer -> Guide 39 describes this.

QUICK TEST ON FEDORA
--------------------
1. Extract the complete IDE to a fresh source folder and build it, OR apply
   the four changed files over a clean Stage 3.45 source tree and rebuild.
2. Back up a working .sbgm project before trying the new workflow.
3. Open the Game Designer: Game Resources -> Add Tile Atlas... -> choose an
   existing compatible .ppb file. It appears in the Tile Atlases group,
   NOT on the game canvas or under Sprites.
4. Open Tilemap Editor and choose that atlas from the dropdown; paint a tile,
   Save/Apply the map, then save the game design.
5. Run Update Project (its own backup-first process), then compile and test
   your game on SIDBOX. Keep the PPB on the SD card at the expected relative
   project path unless you chose to embed assets.
6. Ensure drawworld()/gameassets_draw_foreground() does not draw an unwanted
   full-sheet sprite. The generated gameassets_find_ppb() must still expose
   the chosen tile atlas so game_level1_load_atlas() succeeds.
7. Reopen the saved .sbgm and confirm the resource, atlas selection and map
   preview remain correct. Test a legacy sprite-hosted .sbgm unchanged.
8. If migrating, right-click the old atlas-holder sprite -> Move to Tile
   Atlases. Save and Update Project, then ensure any custom C references to
   its old sprite symbol are removed (if present). Ctrl+Z reverts metadata
   conversion in the resource editor while still editing.

COMPATIBILITY & CAUTIONS
------------------------
- No change to collision IDs, slope data, tilemap editor stamp semantics or
  .map file layout; Stage 3.45 Escape behaviour remains intact.
- The atlas is still one PPB sheet for the current map. This change is NOT
  a multi-atlas runtime renderer; unused bank sheets do not consume SDRAM.
- A changed PPB's tile dimensions/indices must still match the map layout.
- Converting a real player/object/animated game sprite into a tile atlas is
  not permitted via the migration action. Leave actual gameplay sprites in
  the Sprites group. Only ordinary decorative PPB sprites can be moved.
- External PPB files are NOT auto-copied to the SD card, as with previous
  game resources. Preserve the generated path or embed pixels explicitly.
- Regenerate gameassets after migration; existing generated gameassets.c
  might still contain an old sprite until Update Project runs.
