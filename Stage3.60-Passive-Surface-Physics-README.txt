EDITOR USE
----------
1. Rebuild the IDE in Qt Creator.
2. Open Tilemap Editor > Collision Stamps and select a point-defined slope.
   Bezier-generated curves use these same point-defined stamps.
3. Check "Passive surface physics (slide with gravity)".
4. Adjust Damping 0–100% using the slider or spin box:
     0% = no surface momentum loss (ice-like)
     2% = slippery with slight resistance (initial enabled default)
     15% = rougher, motion slows more quickly
     70% = very resistant to sliding
     100% = stops passive/external horizontal momentum on contact
   The damping setting affects external/gravity momentum while grounded;
   joystick walking speed is still controlled by the normal player preset.
5. Give the stamp an appropriate name, e.g. slope2slippery. All placements
   share the SAME setting and follow edits to the original shape. Mirror X
   reverses the calculated downhill direction.
6. Save the map, Update Game Project, regenerate game resources/level1.c and
   the SD .map when applicable. Update gametilemap.c/.h in the GAME PROJECT,
   rebuild the V1 game, and recopy the regenerated SD .map if used.
   The existing user-owned main.c does not require modification.

HOW IT WORKS
------------
- The per-stamp setting is OFF for all existing .sbgm projects and stamps.
- When the character stands on an enabled collision stamp, the runtime finds
  the actual supporting curve segment, projects gravity along its tangent,
  and adds downhill acceleration to the existing force_vx100 velocity.
- The chosen stamp's damping replaces force_drag_percent ONLY for contact
  frames. It does not permanently change the player's physics preset.
- The feature adds no surface array. SD map v4 already stores an 8-byte
  descriptor per point-shape: its previously reserved byte and u16 are now
  damping_percent and surface_flags. Existing v4 files with zero reserved
  data still load unchanged with the NEW helper. Old binaries/old helper
  cannot be assumed to accept newly enabled surface data: UPDATE HELPERS.
- Embedded C export carries identical metadata in shape_defs.
- The result uses integer arithmetic in the V1 player loop; no malloc,
  floating point or per-frame trigonometry.
- Regular painted collision types 3/4 and legacy v3 slope pixels do not
  acquire new settings; the opt-in is for point-defined collision stamps.
- Loop Tracks are a separate circular guiding mode, unchanged by this pass.
