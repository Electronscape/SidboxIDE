SIDBOX GamerGirl Stage 3.50 — Continuous physics-zone transitions
=================================================================
Based on Stage 3.49 (Palette double-click) full IDE.

WHY
---
Stage 3.43's game_tile_player_set_physics() zeroed slide_velocity100 and
slide_remainder100 each time a preset was selected. Consequently moving
from NORMAL into ICE started ice acceleration at zero speed, creating a
little hitch. Switching OUT of ice also discarded any lingering slide.

FIX
---
1. Ordinary walking now remembers the most recent controlled horizontal
   speed, without counting external wind/impulses twice.
2. Selecting ICE inherits that speed and continues accelerating/sliding.
3. Switching to ANY non-ICE preset (normal, slow, water, space, etc.)
   converts prior controlled motion into external momentum, subtracting
   any new walking input so velocities aren't added twice. That momentum
   follows the chosen preset's force_drag_percent (including 0% in space).
4. Preset transitions from rest do not cancel the first joystick movement.
5. Repeated set_physics_ice() calls no longer wipe sliding velocity.
6. Vertical velocity, spring physics, existing external forces, and all
   collision checks remain on their original paths. Respawn STILL resets
   momentum intentionally.

Only two game helper source files changed:
    idelibs/codehelpers/game/tilemap.c
    idelibs/codehelpers/game/tilemap.h

INSTALL
-------
1. Back up your working SIDBOX IDE and game project.
2. Use the changed-files archive to replace the two files above in the
   IDE source directory. Or start with the full Stage 3.50 source archive.
3. Rebuild your Fedora IDE.
4. In the Game Designer use Update Game Project and ACCEPT the normal
   backup-first helper refresh, then rebuild Platformer3. Existing main.c
   is NOT overwritten, and your custom zone callbacks can stay as they are.
5. Test entering ice holding RIGHT (no hesitation), releasing controls
   while leaving ice (keeps coasting briefly), and hitting solid walls
   (still blocks). Test zero-gravity zones again too.

No SIDBOX OS / LCD firmware flashing or SD map changes.

NOTES
-----
- Preset values (gravity, jump speed, drag, walk speed) still take effect
  immediately; it's the player's existing velocity that remains continuous.
- In NORMAL mode, inherited ice motion decays via the normal 12% force drag.
  WATER uses 18%; SPACE has zero drag so it can keep coasting.
- A preset changes gravity/walk/jump parameters immediately; momentum
  carries through, so switching from fast to slow terrain feels like
  deceleration rather than a sudden stop. The same collision solver runs.
- The existing maingame.c.txt examples using GAME_ZONE_ENTERED and EXITED
  work without modification.
- Don't call game_tile_player_reset() to switch zones: that intentionally
  resets all movement. A custom EXITED callback should set the desired
  preset (or custom values); overlapping zones need programmer-defined
  priority, as before.
